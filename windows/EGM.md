# windows Blueprint

## System Overview
Windows desktop platform host for the Flutter app (`ver2_app`), generated by `flutter create`. It is a CMake project that builds a Win32 executable embedding the Flutter engine and installs the engine, ICU data, assets, plugin libraries, and (non-Debug) the AOT library next to the executable. It contains no application logic; all app behavior lives in the Dart code at the repo root.

## Local Interface & Invariants
- `CMakeLists.txt` (project `ver2_app`, C++17, `/W4 /WX`, Unicode defines):
  - `BINARY_NAME` is `ver2_app`; this is the one place to rename the executable.
  - Configurations: `Debug`, `Profile`, `Release`. Profile flags mirror Release.
  - `APPLY_STANDARD_SETTINGS(TARGET)` is applied to the runner and Flutter wrapper targets.
  - Subdirectories are added in order: `flutter`, `runner`, then `flutter/generated_plugins.cmake` is included.
  - Install step copies into `$<TARGET_FILE_DIR:ver2_app>`: the executable, `flutter_windows.dll`, `icudtl.dat` and `flutter_assets` (under `data/`, re-copied from scratch each build), plugin bundled libraries, native assets, and `app.so` (Profile and Release only).
- `.gitignore` excludes `flutter/ephemeral/` and Visual Studio user and cache files.

## Subdirectories & System Boundaries
- flutter: [./flutter/EGM.md](./flutter/EGM.md) - Flutter-tool-managed CMake and generated plugin registrant (`RegisterPlugins`); currently registers `geolocator_windows`.
- runner: [./runner/EGM.md](./runner/EGM.md) - `wWinMain`, `Win32Window`, `FlutterWindow`, resources, and manifest that host the Flutter view.

## Global Invariants
- Generated files (`flutter/generated_plugin_registrant.*`, `flutter/generated_plugins.cmake`, `flutter/CMakeLists.txt`) must not be hand-edited.
- `flutter/ephemeral/` is produced by the Flutter tool and must exist before building.
- The plugin list is derived by the Flutter tool from the dependency graph of the repo-root `pubspec.yaml` (`geolocator` is a direct dependency; `generated_plugins.cmake` lists `geolocator_windows` as a plugin and `jni` as an FFI plugin).

## Global Side Effects
- Building runs the Flutter tool (`flutter_assemble`) and produces the Windows bundle under the Flutter `build/` directory.
- At runtime, the executable touches the console, COM, the registry (theme read), and DWM window attributes (see runner contract).

## System Verification
- Run from the repo root (`PollutionViz-Frontend`): `flutter build windows` (requires a Windows host with Visual Studio C++ tooling) and `flutter analyze`.
